  ```env
  PAYSTACK_PUBLIC_KEY=pk_live_1ed764614ba0e2993ae08d6312e2cccb9a5e6c69
  ```

### Paystack Implementation Details
- **Checkout Flow**: Handled via `PaystackCheckoutModal` using an in-app WebView loading the official transaction `authorization_url` generated by `POST /api/subscriptions/initialize-payment` and `POST /api/payment/paystack/initialize-order`.
- **Instant Verification**: On modal close or redirect, the app verifies the transaction via `POST /api/subscriptions/verify-payment` or `POST /api/payment/paystack/verify/:reference` before updating UI state.

## 3. Google Pay (Android)

Google Pay provides one-tap checkout using payment credentials stored in the user's Google Wallet.

### Current Status in Code
- **API Enabled in Manifest** (`android/app/src/main/AndroidManifest.xml`):
  ```xml
  <!-- Enable Google Pay API -->
  <meta-data
      android:name="com.google.android.gms.wallet.api.enabled"
      android:value="true" />
  ```
- **Configuration** (`foam_mobile-main/lib/core/services/foam_payment_service.dart`):
  Tokenization specification is set to `PAYMENT_GATEWAY` targeting gateway `paystack` with your live public key.
- Currently in **`TEST`** mode so any Android device/emulator with test cards can simulate checkouts without charging cards.

### Production Setup Steps
1. **Google Pay Business Console**:
   - Visit the [Google Pay & Wallet Business Console](https://pay.google.com/business/console).
   - Sign up with your company Google account and complete business profile verification.
2. **Obtain Production Merchant ID**:
   - Once approved, navigate to your profile settings to find your **Merchant ID** (format: `BCR2DN6TX...` or a 20-digit numeric ID).
3. **Switch to Production in Code**:
   In `foam_mobile-main/lib/core/services/foam_payment_service.dart` (around line 50), update `_googlePayConfigJson`:
   ```json
   "environment": "PRODUCTION",
   "merchantInfo": {
     "merchantId": "YOUR_ACTUAL_GOOGLE_MERCHANT_ID",
     "merchantName": "Foam Laundry"
   }
   ```
4. **Google Play Store Approval**:
   - Submit your app APK/AAB to Google Play Console.
   - Request Google Pay production access inside the Google Pay Business Console by linking your Play Store package name (`com.example.foam_mobile` or your production applicationId).

## 4. Apple Pay (iOS)

Apple Pay provides frictionless Face ID / Touch ID authorization on iOS devices.

### Current Status in Code
- **Entitlements Configured** (`ios/Runner/Runner.entitlements`):
  ```xml
  <key>com.apple.developer.in-app-payments</key>
  <array>
      <string>merchant.com.foamlaundryapp</string>
  </array>
  ```
- **Configuration** (`foam_mobile-main/lib/core/services/foam_payment_service.dart`):
  Configured with merchant identifier `merchant.com.foamlaundryapp`, 3DS capability, and NGN currency.

### Production Setup Steps
1. **Create Merchant ID in Apple Developer Portal**:
   - Log in to [developer.apple.com](https://developer.apple.com).
   - Go to **Certificates, Identifiers & Profiles** -> **Identifiers**.
   - Click the **`+`** button -> Select **Merchant IDs** -> Click **Continue**.
   - Description: `Foam Laundry Merchant ID`
   - Identifier: `merchant.com.foamlaundryapp`
2. **Generate Payment Processing Certificate for Paystack**:
   - Open your [Paystack Dashboard](https://dashboard.paystack.com).
   - Navigate to **Settings** -> **Preferences** / **Payment Methods** -> **Apple Pay**.
   - Download the **Certificate Signing Request (CSR)** file provided by Paystack.
   - Return to the Apple Developer Portal -> Select your `merchant.com.foamlaundryapp` identifier.
   - Under **Apple Pay Payment Processing Certificate**, click **Create Certificate**.
   - Upload the CSR file from Paystack.
   - Download the resulting `.cer` file from Apple, return to Paystack, and upload the certificate.
3. **Xcode Signing & Capabilities**:
   - Open `ios/Runner.xcworkspace` in Xcode.
   - Select the **Runner** target -> **Signing & Capabilities** tab.
   - Ensure the **Apple Pay** capability is enabled and the checkmark next to `merchant.com.foamlaundryapp` is checked.

## 5. Mobile App Flow & User Roles

- **Customer Accounts (`role: "USER"`)**:
  - Direct checkout via **Google Pay**, **Apple Pay**, or **Paystack**.
  - No wallet system is displayed or required for customers.
  - The side drawer and profile screen display a **"Become a Vendor"** shortcut that routes to `VendorSignUpScreen.id`.
- **Vendor Accounts (`role: "VENDOR"`)**:
  - The side drawer and profile screen display the **"Vendor Management Portal"** shortcut routing to `VendorMainScreen.id`.
  - Vendors retain access to vendor earnings, stores, and payout banking setup.
